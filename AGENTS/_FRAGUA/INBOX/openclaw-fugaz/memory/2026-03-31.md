## HODOM migración CSV → PostgreSQL (review para Felix/Ominono)

- **Contexto**: ~31 CSV de registros de hospitalización domiciliaria, Hospital San Carlos, Ñuble, Chile (ene 2024 – mar 2026)
- **Pipeline**: script Python (`migrate_hodom_csv.py`) generado externamente en Mac de Felix, artefactos enviados para review
- **Artefactos recibidos**: README, schema SQL, reporte JSON, resumen fuentes, pacientes, duplicados, episodios deduplicados, episodios raw
- **Resultados**: 2998 raw → 1757 episodios deduplicados, 1298 pacientes, 30 archivos fuente procesados
- **4 schema variants**: p26 (26 cols), p27 (2026), p40 (43 cols split names), p43 (43 cols), p43_headerless
- **Review dado**: pipeline sólido como primera iteración, trazabilidad excelente, dedup key correcta
- **Problemas detectados**:
  - 🔴 RUT no normalizado — fechas parseadas como RUT en variante B (`rut:011936040000-0400`), ~30-40 pacientes fantasma
  - 🔴 RUT con puntos/guiones no colapsados — mismo paciente con patient_keys distintas
  - 🟡 Fechas malformadas sin fallback (`09-04-02024`, `16-01-204`)
  - 🟡 Sexo incorrecto heredado de columnas desplazadas
  - 🟡 Pacientes `anon:` sin RUT → hash anónimo, no mergeable
  - 🟠 Barthel no normalizado (`DEP. LEVE` vs `D.LEVE` vs `D. LEVE`)
- **Recomendaciones**: normalizar RUT antes de deduplicar, segundo paso de patient merge, validar contra NO_MOD.csv, regex fallback para fechas
- **Estado**: pendiente decisión de Felix sobre si corregir pipeline o cargar y validar post-carga

- **Binario**: `h` (Go, ~9.5MB estático)
- **Propósito**: acceso atómico a sistemas clínicos DAU/SGH/Lab del Hospital de San Carlos
- **Consumidor principal**: agente OpenClaw (steipete/urgencista)
- **Output**: JSON a stdout (default), texto con `-t`
- **Arqueología**: 4 generaciones previas en `/home/felix/projects/hsc-cli/arqueologia/cli-hsc/`

### Infraestructura
- Tailscale instalado en hetzner2897261 (100.95.142.39) por Clawforge
- Ruta: hetzner2897261 → Tailscale → HODOM (100.77.30.26) → netsh portproxy → Red MINSAL
- DAU :8080 ✅, SGH :8085 ✅, LAB :8084 ✅ (latencia 0.5-0.8s)
- Config Tailscale: `--accept-routes=false --accept-dns=false --shields-up`

### Credenciales
- Env vars: `H_DAU_PASS`, `H_SGH_PASS` (extraídas de skill dau-sgh legacy en clawdbot-hetzner)
- Defaults hardcoded: user=fsanhuezal, servicio=4, institucion=4, usuario_id=3225

### Comandos implementados (5 commits)
```
LECTURA DAU: h box, h who, h tri, h sv, h nota, h dx, h obs, h labs, h rx
LECTURA SGH: h hx, h evo, h camas
ESCRITURA:   h w nota (read-modify-write), h w dx, h w alta, h w evo
SESIÓN:      h status, h login, h logout, h pt
EN PROGRESO: h sala, h cola, h alx
```

### Decisiones de diseño clave
- Go binario estático (no Python wrapper)
- JSON default (consumidor = agente)
- Paciente enfocado sticky (`h pt`) + inline override
- Read-modify-write obligatorio en escritura DAU (previene incidentes I20/I21/I25)
- 800 chars max por campo DAU, trunca con warning
- ctx/docs postergados a F5 por recomendación de Allan Kelly
- Sin SQLite local para v1
