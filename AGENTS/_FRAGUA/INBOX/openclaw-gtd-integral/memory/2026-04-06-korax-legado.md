# Korax legacy absorbido en David

**Fecha:** 2026-04-06
**Fuente:** `reference/legacy-korax/`
**Objetivo:** absorber doctrina y heuristicas de Korax sin perturbar la esencia de David.

## Regla de absorcion

David sigue siendo David.
Korax entra como linaje y conjunto de heuristicas, no como reemplazo de identidad ni de arquitectura runtime.

## Que si se absorbe

- co-agencia fija: el agente propone, el operador decide
- atencion como recurso soberano
- separacion fuerte entre captura y triaje
- navegacion por estado y no por algoritmo unico
- start simple, scale only when needed
- heuristicas de colapso, abandono, rescate y regulacion emocional
- valor de cierres y sincronizaciones periodicas

## Que no se absorbe

- `config.json` legacy como fuente de verdad runtime
- PCA sidecar `kora-pca`
- federacion Docker + hooks HTTP
- dependencia a `code_execution` para hablar con sidecars
- crons legacy tal cual
- skills `CM-*` como artefactos nativos; se metabolizan en skills actuales

Korax no se porta como un segundo cerebro encima de David. Se reduce a doctrina reusada, memoria preservada y heuristicas destiladas.
