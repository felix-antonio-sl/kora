HALLAZGOS CRÍTICOS (2)

H1. VIOLACIÓN DEL PRINCIPIO DE UNICIDAD DE ROL PROCEDURAL — SD1

ISO establece: "an object or state has exactly one role (transformee or enabler) with respect to a linked process."

En SD1, Care Planning tiene simultáneamente:
- `Care Planning yields Therapeutic Plan in draft` (resultee)
- `Care Planning changes Therapeutic Plan from draft to active` (affectee)

Therapeutic Plan tiene DOS roles transformadores respecto al mismo proceso. Misma violación con Nursing Care Plan.

Adicionalmente, la tabla de precedencia de out-zooming (§8.4) dice: cuando un subproceso P1 tiene result link y otro P2 tiene effect link al mismo objeto, al nivel padre la precedencia es Result > Effect → solo Result sobrevive. En SD1, Care Planning (aún no in-zoomed en SD1.3) debería mostrar solo:
```
Care Planning yields Therapeutic Plan in active.
Care Planning yields Nursing Care Plan in active.
```
La transición draft→active es un detalle interno de SD1.3. Mostrar ambos links en SD1 viola unicidad de rol + precedencia de out-zooming.

Corrección: en SD1, eliminar los `changes ... from draft to active`. Cambiar el state-specified result a `in active` (estado final neto del subproceso).

H2. DOBLE ROL ENABLER + TRANSFORMEE EN PLAN ACTIVATING — SD1.3

```
Plan Activating changes Therapeutic Plan from draft to active.
Plan Activating requires Therapeutic Plan in draft.
```

Therapeutic Plan es simultáneamente instrument (requires) y affectee (changes) de Plan Activating. Viola el mismo principio de unicidad de rol (ISO §Procedural links). El input-specified effect link (`changes from draft to active`) ya implica que el objeto debe estar en `draft` como precondición. El `requires` es redundante y crea el conflicto de roles.

Misma violación con Nursing Care Plan.

Corrección: eliminar las dos sentencias `requires` de Plan Activating. Los effect links con input state especificado ya portan la precondición.
