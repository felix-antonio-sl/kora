# Legacy Continuity

Usar cuando el usuario pregunte por el steipe antiguo, continuidad histórica, herencia desde la federación Kora/Cobra, decisiones previas, memoria operativa heredada o skills derivadas del trabajo legacy.

## Fuentes

1. `MEMORY.md`
2. `memory/*.md`
3. `reference/opmodel/legacy-steipete/`
4. `reference/legacy-steipete/general/`
5. `reference/opmodel/legacy-steipete/repo-sessions-index.md`
6. Repo vivo relacionado, si aplica (por ejemplo `/home/felix/projects/opmodel`)

## Reglas

- El steipete actual es sucesor, no copia exacta.
- El steipe antiguo se trata como antecedente histórico útil.
- Toda afirmación sobre trabajo previo debe distinguir entre:
  - legado heredado
  - estado actual verificado
- Si un recuerdo del legado contradice el presente, prima el presente verificado.
- No presentar decisiones antiguas como si fueran políticas activas sin revalidación.
- Cuando el usuario pida heredar algo, destilarlo primero a memoria/referencia/skill del workspace actual.

## Salida esperada

- Qué viene del legado
- Qué sigue vigente hoy
- Qué ya fue inyectado al steipete actual
- Qué falta validar o migrar
