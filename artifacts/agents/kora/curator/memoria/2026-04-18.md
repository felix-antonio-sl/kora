# 2026-04-18

## Cambio principal

- `atomize` quedo consolidado como productor canonico de `atomic`, runtime-agnostic para Claude Code y Codex.
- El skill ya no se apoya solo en lint estructural: ahora exige quality review, fidelity packet y acceptance review persistente antes de publicar via wrapper.

## Decisiones operativas

- El juicio de fidelidad semantica sigue siendo del agente/humano; los scripts solo preparan evidencia y gates.
- `publish_atomic.py` bloquea la promocion si no existe una review aceptada y fresca para el bundle.
- `review_atomic_acceptance.py` aumenta el muestreo cuando detecta `tension` y deja `bundle_stats` persistentes.
- Los golden cases cubren libro `.txt`, OCR sucio, dedup multiarchivo y conflictos reales (`tension`) por numero, negacion y excepcion.

## Estado de referencia

- Se conservaron dos bundles de `opm-libro` en `KNOWLEDGE/_SCRIPTORIUM/REVIEW/kora/atomic/`:
  - `atomic-opm-libro-*` como contraejemplo de corrida mala
  - `atomic-opm-libro-rebuilt-*` como baseline aceptable de recuperacion
- `atomic-opm-libro-rebuilt-review.md` existe y esta en `decision: reject`; sirve como cierre honesto de estado, no como bundle publicable.

## Regla a recordar

- Para `atomic`, `lint OK` nunca basta.
- Si el bundle colapsa hechos distinguibles, pierde condiciones o deja pasar paratexto como proposiciones, la corrida no cerro aunque los checks mecanicos pasen.
- El siguiente salto de rigor pendiente es subir parte del acceptance gate al core (`toolchain/kora promote`), porque hoy la obligacion fuerte vive en los wrappers del skill.
